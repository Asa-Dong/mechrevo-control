# 先验证能力，再实现

## 语言与权限边界

Zig 用户态程序不能直接调用 Linux 内核函数 acpi_evaluate_integer。之前的 ECRR 验证由临时 C 内核模块完成；本项目不再加载该模块。实现路径优先为：

GNOME JavaScript UI → D-Bus → Zig 服务 → sysfs/ioctl 驱动接口 → ACPI/EC。

Zig 可以直接调用 libsystemd、Linux ioctl 等 ABI，但不会因此绕过内核驱动和权限要求。先复用、适配成熟驱动；不要通过 /dev/mem 或任意 ACPI 执行器绕过接口。现阶段为普通用户只读服务；未来写入由独立系统服务、明确 API、设备白名单和 Polkit 授权承载。

## 0.4.7 控制范围

曲线 UI 最低 20%，服务与驱动接受 0–100%，不再强制末档/更高温区 100%。移除手动 CPU≥80°C / GPU≥75°C 全速覆盖及温度异常释放，删除 fan_override 状态接口；保留通信错误恢复和正常生命周期释放。本机已实测曲线 0%/10% 输出仍为 25%；不修改 EC 自身逻辑，不声称其高温兜底已验证。

## 曲线编辑器更新（2026-11-09）

CPU、GPU 使用独立可拖动图表；界面下限改为 0%，移除重复的数值输入框，读取 0% 不再抬升为 20%。拖动只编辑草稿，上调节点时后续较低节点同步抬高，下调不低于前一点，保持每路曲线非递减，点击应用才写固件。当前产品接口仍为每路 40/50/60/70/80°C 五个温区；底层每路 16 项表含哨兵与高温尾段，并不等同于已开放 16 个用户节点。Windows 官方控制中心开放的节点数及可调温度范围未确认。

### 性能模式与曲线并存

曲线启用不再清除 0x0751 的性能位 0xb0，仅清除全速增强位 0x40。退出曲线保留当前性能模式；菜单或实体键切换性能模式时重新启用曲线。此改动不添加 CPU/GPU 功耗参数，也不等同于 Windows 自定义 profile 的完整功能。实体键路径已修改，仍需按键实测。

### 曲线节点与固件温区对齐

节点控制右侧温区：40°C 节点写入 50°C 上限项，以此类推；40°C 以下请求 0%。兼容读取旧上限布局，下一次应用时迁移。此前仅调整绘图造成显示与下发温区相差一档，现修正驱动布局。短时测试曾观察到低温 0% 降速后在 25% 保持；用户后续确认等待更久可以停转，详见下文。

### 曲线响应延迟与撤回一次性 PWM 同步

用户确认曲线可以降到 0 RPM，只是响应较慢，并反馈 Windows 控制中心提供风扇响应速度选项。此前观察 40 秒后停在 25% 不足以判定不能停转。按用户要求撤回 CPU 一次性 PWM 同步；进入、重新应用和运行曲线均不写即时 PWM，保持 EC 自主调速。响应速度选项的 EC 协议尚未确认，未添加该控制。
