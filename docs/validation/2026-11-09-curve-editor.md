驱动 0.4.2：手动范围扩大到 0–100%，保留原有温度保护；曲线最低值未改。曲线表采用已验证的 MMIO 读回，减少 WMI 读取并跳过相同表字节；每次实际写入仍校验。已经处于曲线模式且请求相同曲线时不重写表。首次应用仍用临时全速保护，不声称完全消除此现象。

初次安装遗漏扩展打包的问题已纠正，安装目录包含 prefs.js 与 curveEditor.js。之前会话缓存 hasPrefs=false，不影响重新登录后的入口。

## 曲线低占空比实测（0% / 10%）

临时测试模块放开下限，通过 sysfs 写入两路低温前三档 10%、后两档 80/100%。30 秒内 CPU 47°C，两路 1482–1491 / 1565–1570 RPM。EC 表 0f20/0f50 读回 `00 14 14 14 a0 c8 …`，证明 10%（20/200）确实写入；输出 1804/1809 经 WMI 读回均为 0x32，即 25%（50/200）。与此前 0% 测试相同，当前协议/固件曲线模式下低值输出被保持在 25%，不代表手动模式也有此限制，也不证明其他未验证固件控制位无法改变此行为。

测试后恢复原曲线和固件控制，重新加载正式 0.4.6 模块并启动服务。日志收集命令因 sudo 环境找不到 rg 中断，恢复 trap 已执行；随后补存内核日志并卸载只读诊断模块。记录见 curve-ten-2026-11-09.log。
