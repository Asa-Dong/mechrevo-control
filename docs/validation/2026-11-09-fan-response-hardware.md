# 风扇响应速度候选地址实机验证

仅测试静态分析找到的候选地址 0x0787；未猜测或修改额外启用位。当前机器 X6xR55xK，内核 6.12.116+deb13-amd64。

初始 ACPI 读回为 0。诊断模块核对 WMI/ACPI 读回一致后，分别写入原始值 3、6 并确认读回。假设来源是 Windows 符号 `T100mSec` 与保存值 300；这并不等于已经确认合法范围或单位转换。

## 第一轮测量

暂停系统服务，保存用户设置。CPU 使用恒定 40% 曲线，等实际 PWM 收敛到 40%，然后应用恒定 60% 曲线。GPU 保留用户原曲线。每约 2.3 秒记录实际 PWM、RPM、CPU 温度、性能与风扇模式。记录中 CPU 约 48–56°C，last_error 始终为 0。

| 0x0787 原始值 | PWM 40→59% 采样跨度 | 线性拟合变化率（百分点/秒） |
|---|---:|---:|
| 0（原始） | 11.51 秒 | 1.638 |
| 3 | 11.51 秒 | 1.626 |
| 6 | 11.49 秒 | 1.679 |

结果没有显示响应速度随该地址数值发生明显变化。可写、可读回不等于功能生效。

每个候选值测试后卸载诊断模块并读回确认恢复为 0。诊断模块另外设有 180 秒自动恢复。最终恢复用户曲线、性能与风扇模式并重新启动系统服务。

原始数据：`fan-response-measure.log`。诊断模块：`diagnostics/fan-response/`。当前生产驱动没有新增响应速度接口。

## 复查应用曲线后是否丢失候选值

再次测试原始值 6，在应用 60% 曲线后加载只读探针，读到 `0x0787=0x06`，排除了应用曲线时被立即重置的解释。实际 PWM 仍以约 1.6–1.7 个百分点/秒上升。结束恢复日志为 `restored raw=0`。

复查数据：`fan-response-recheck.log`；关键寄存器读回及恢复日志：`fan-response-registers.log`。

结论：在当前控制位组合下，单独修改 0x0787 未观察到 CPU 曲线上升速度改变。尚不能排除需要独立启用位、特定 Windows 后端或不同参数转换；降速及停转等待计时也未由本实验验证。下一步需对比 Windows 启用/禁用该选项时的实际 EC 变化，不能据此猜测修改其他位。

## 最高位启用假设验证：成功

用户 Windows 截图补充范围 100–12700 ms/0.5%，当前 11600 且勾选启用。由此提出 bit7 为启用位、低 7 位以 100 ms 为单位的假设，受控测试 0x83、0x86。

本轮初始为服务 inactive、control=firmware、办公+自动，曲线无有效产品布局。加载备份模块只读保存完整 96 字节表和相关控制位后才开始实验。测试 CPU 固定 40%→60%，GPU 固定 40%，未加载 CPU/GPU 压力程序。读回证明曲线应用后 0x0787 仍为对应测试值。

| 原始值 | CPU PWM 上升速率（百分点/秒） | 换算每 0.5% 时间 |
|---|---:|---:|
| 0x00 | 1.693 | 295.3 ms |
| 0x83 | 1.646 | 303.7 ms |
| 0x86 | 0.832 | 600.7 ms |

线性拟合仅使用 PWM 为 40–59% 的采样，排除写表时门控切换瞬态和达到目标后的限幅。结果支持 `0x80 | (毫秒 / 100)` 的编码；上一轮 0x06 未生效、这一轮 0x86 明显减慢，也支持 bit7 为启用位。0x00 在本机本次测试下约为默认 300 ms/0.5%，不宣称适用于所有模式/固件。

验证边界：本轮测的是 CPU 上升过程；GPU 动态变化、下降过程、端点 100/12700、关闭后具体恢复策略和持久性尚未验证。产品驱动与 UI 尚未新增该设置。

结束确认：候选地址恢复为 0；原始 96 字节表逐字节恢复，控制位恢复；重载产品模块清除实验产生的缓存；最终 control=firmware、办公+自动、last_error=0，服务仍 inactive。

记录：`fan-response-highbit.log`、`fan-response-highbit-registers.log`。
