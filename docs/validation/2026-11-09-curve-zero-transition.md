# 曲线零转速的状态依赖

> 后续更正：用户确认曲线模式等待更久可以停转，之前的短时观察不能证明存在固定 25% 下限。CPU 一次性 PWM 同步已按用户要求撤回。以下保留当时的测试记录，不代表当前实现。


用户报告低温曲线 0% 仍转，先手动停转再进入曲线可保持停转。实机采用修改后保留性能模式的 1.2.0 驱动，暂停服务后直接 sysfs 测试，结束恢复原曲线和模式并重新启动服务。

- 初始办公 + 曲线，CPU 48°C，曲线前两档 0%，实际 PWM 25%/0%，RPM 1495/0。
- 自动 → 原曲线：48–50°C 时 PWM 和 RPM 均为 0。
- 手动 0%：CPU 升至 50–51°C，PWM 读数为 0，但 CPU 实际仍约 1500 RPM。
- 手动 → 原曲线：CPU PWM 升至 37%。原有表的第三档上限是 60°C，实际从约 50°C 起进入该档；UI 画成从 60°C 起，这是已确认的映射错误。
- 两路曲线 60%：PWM 均收敛 60%，RPM 约 3270/3420，CPU 降至 46°C。
- 再恢复原曲线前两档 0%：观察 40 秒，PWM 从 47% 逐步下降到 25% 后保持，RPM 约 1495/1557，CPU 44°C。

原始记录：`curve-zero-transition.log`。这些实验改变的是曲线目标，不是 CPU/GPU 负载；不能代替自然升温/降温跨档验证。进入曲线后手动刷新已停止，未发现驱动定期写入 25% 的代码。

本次修复图表/固件温区错位：使用额外的 40°C 零请求项，五个节点写入 50/60/70/80/90°C 上限项，保持节点控制右侧温区。读取兼容旧表，下次显式应用或服务恢复保存曲线时迁移。单元测试验证 21–99°C 各段请求及新旧布局读取。

停转状态依赖尚未修复，不能宣称是硬件绝对最低 25%，也不能宣称 0% 能保证停转。未添加主机温度循环或强制持续零 PWM。
