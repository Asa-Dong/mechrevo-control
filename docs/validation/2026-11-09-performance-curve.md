# 性能模式与 EC 曲线并存

在当前机器、6.12.116+deb13-amd64 上安装修改后的 1.2.0 驱动进行实机验证。

修改：曲线启用仅清除 0x0751 的全速增强位 0x40，保留性能位 0xb0；退出曲线不回写旧性能位。性能模式切换后重新启用曲线，实体模式键走相同逻辑。

三档模式分别写入双路恒定 40%/80% 曲线，性能模式读回与曲线状态均保留。短时间 RPM 尚未达到目标，进一步读取 PWM 确认固件逐步平滑加速，不能以最初 8 秒读数判定失败。

稳定性检查：办公、均衡、狂暴依次与恒定 80% 曲线并存，两路实际 PWM 均到达 80%；CPU 风扇约 4090 RPM，GPU 风扇约 4240 RPM。再在狂暴模式下降至 40%，两路实际 PWM 均收敛到 40%，RPM 约为 2326 / 2455。原始记录见 `performance-curve-coexist.log`。全部测试未施加 CPU/GPU 负载，CPU 温度约 42–48°C。

测试使用直接 sysfs 写入，期间停止系统服务，结束恢复原曲线、办公和自动风扇，再启动服务；不修改用户保存的配置。回归脚本：`tests/performance-curve.py`，必须显式设置 `MECHREVO_HARDWARE_TEST=1` 并以 root 运行。

边界：未实测实体模式键、重启/休眠、高温分档；未验证三档模式的 CPU/GPU 功耗效果。本次没有开放 Windows 自定义 profile 的 CPU/GPU 功耗参数。

## 用户灯色反馈

用户确认：新版保留办公高亮后，选择曲线仍会使模式键灯变白。同时 sysfs 读回 `mode=office`、`fan_control=curve`。因此此前将白灯归因于清除性能位的解释不充分；曲线同时开启的自定义标志可能参与灯色选择，但尚未定位具体位或独立灯控接口。保留性能位与 PWM 收敛测试不能证明 CPU/GPU 功耗策略仍等同于办公预设，需单独验证。
