# 菜单 v3 修正

用户确认问题是点击控制子菜单无法展开，而不是选择后写入失败。普通用户通过系统 D-Bus 的 mode 原值写入经 Polkit 认证成功，随后 release 成功，控制权恢复固件。

更新：

- 主菜单缩减为 CPU/电池摘要、双路 RPM、三档按钮、全速开关、亮度/颜色/充电配置按钮。
- 当前选择高亮，详细传感器与恢复操作收进“更多信息”，详细区域有滚动高度限制。
- 不再使用控制子菜单；不在刷新或操作过程中 removeAll 重建菜单，保留按钮与焦点。
- 应用期间显示状态、阻止重复提交；请求携带允许交互认证标志，错误以中文反馈。

在独立 dbus-run-session、GSETTINGS_BACKEND=memory 的 GNOME Shell 48.7 headless 会话中测试新版，未替换用户正在运行的 Shell：

- 真实驱动 GetStatus 读取成功。
- 15 个控制按钮均关联正确的 setting/value。
- 虚拟鼠标实际点中狂暴按钮并触发对应处理函数；此 UI 测试的写函数被替换为记录器，不写硬件。
- 刷新保持同一按钮对象，菜单保持打开。
- 主菜单高度低于 650 逻辑像素，在 1280×900 下完整显示。
- 更多信息可展开且具有非零可见高度。
- enable/disable 生命周期及截图通过，JS 语法检查通过。

测试代码见 tests/menu-ui.js。扩展 v3 已打包安装；当前桌面缓存着 v2 JavaScript，需用户注销再登录加载新版，未强制结束会话。控制链路已分别验证，不将隔离环境的按钮记录器称为用户桌面端到端写入验证。
