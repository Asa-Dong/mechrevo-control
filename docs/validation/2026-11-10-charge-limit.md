# 100 / 80 / 60 百分比限充调查

前半为最初调查；同日后续已接入 1.4.0 并验证设置、取消及服务/模块重载，见文末“1.4.0 产品接入”。实际充电跨阈值验收仍未完成。

## 目标与现状

目标为长效 100%、日常均衡 80%、工作站长寿 60%。验收应覆盖实际充电至上限停止、低于恢复条件后重新充电、切回 100% 后恢复充电，以及服务重启、睡眠和整机重启后的行为。设定值读回不等于上述验收通过。

用户实测：电量约 65% 时开启当前工作站模式，仍充到系统显示 100%。当前 `0x07A6` 三档接口没有实现预期的百分比限充；它可能调整充电策略，不能据此认定所有充电参数都毫无变化。

本次新增的模块只属于诊断工具，未修改产品驱动、三档按钮或启动偏好。100 / 80 / 60 的最终目标尚未完成。

## open-revo 源码对照

参考仓库：https://github.com/faintonce/open-revo ，固定提交 `b7d2b526e60cd04965eadab21e606bdb1e1aa56e`。未安装或运行其 Windows 程序。

- `src-tauri/src/driver/ec_bridge.rs` 的 `apply_battery_limit_with_override`：设置上限 `0x07B9`、下限 `0x07D0`（上限减 5）和 `0x07A6` 档位。旧同方路径启用实验硬件限充时，将 `0x07C3` 持续设为 4；其 watcher 会在平台值变化后重新写回 4。它还向 ROM ID 首字节 `0x0770` 写 `0xFF`，本次没有照搬此操作。
- `src-tauri/config/ec_registry.json`：100/80/60 对应模式字节 1/17/33；平台地址为十进制 1987（`0x07C3`），不是 ROM ID 地址 1904（`0x0770`）。
- `commands/power_cmd.rs` 的 `set_battery_mode` 先保存偏好，再启动后台写入；`ec_bridge.rs` 也先更新缓存。其成功返回、缓存显示或 README 中的“闭环养护”不能单独证明硬件实际停充。
- `resources/drivers/jiaolong_16_bld.json` 对另一种宝龙达平台声明 `battery_charge_limit=false`；对应底层充电写入已禁用。不能因为名称同为蛟龙就视为同一平台，也不能据该文件认定本机 INOU 同方通道不支持。

相比之下，[Leo-stro 的方法](https://github.com/Leo-stro/mechrevo-charge-limit/blob/75a8061472a2b9ca07b49f35601c21ba4c735c1f/docs/FINDINGS.md)只短暂将平台值设为 4，恢复后依靠存储上限继续启用。这是两个方案的重要区别。

## 本机与测试方法

- DMI：MECHREVO / `JIAOLONG Series-X6xR55xK`；BIOS `N.1.12MRO13`；内核 `6.12.116+deb13-amd64`。
- 交流电在线，BAT0 为 100% / Full，`current_now=0`。因此无法验证从低电量充电跨越 60% / 80% 的实际行为。
- 先停止系统服务、卸载产品模块；使用固定寄存器诊断模块；测试结束卸载诊断模块、重新加载产品模块并启动系统服务。现有 EC 风扇曲线保留，系统服务恢复已保存偏好。
- 没有写 `0x0770`、下限 `0x07D0` 或存储地址 `0x087F`；没有刷 BIOS / EC。

## 可恢复写入测试

第一次经 WMI 写 80%，短暂开启平台值 4 后恢复 7，等待 7 秒：实时上限和存储上限都是 80，但门控仍为 `0x22`，没有 bit2。随后清零，两处均回到 0，平台值恢复 7。测试失败，未继续该轮 60%。

第二次使用与参考脚本相同的 ECRW 直接写入路径，增加临时门控期间的读数；所有状态通过 WMI 邮箱读取：

| 目标 | 平台值 4 保持 2.5 秒时：门控 / 实时 / 存储 | 恢复平台值 7 后等待 7 秒：门控 / 实时 / 存储 |
| --- | --- | --- |
| 80% | `0x26 / 0xD0 / 0x50` | `0x22 / 0x50 / 0x50` |
| 60% | `0x26 / 0xBC / 0x3C` | `0x22 / 0x3C / 0x3C` |
| 取消 | `0x26 / 0x00 / 0x00` | `0x22 / 0x00 / 0x00` |

`0xD0` 是上限 80 加 bit7，`0xBC` 是上限 60 加 bit7。平台值为 4 时，门控和“已达上限”标志都能激活；恢复平台值 7 后，它们清除，尽管存储上限仍是合法值。**因此，当前本机固件不符合参考项目“保存一次后门控保持”的预期。** 不能只检查上限读回和存储读回便报告成功。

最终 `TEST result=-61`（`-ENODATA`，门控验收未通过），`RESTORE result=0 pending=0`，卸载时 `platform_pending=0`。临时平台值在每一步均恢复到 7，ROM ID 始终为 `0xFF`，最终上限和存储值为 0。

日志：[WMI 首轮](charge-limit-transactions-2026-11-10.log)、[直接 ACPI 第二轮](charge-limit-acpi-transactions-2026-11-10.log)。模块返回加载成功是为了在恢复失败时保留卸载重试机会，不能作为测试通过依据。

## 下一步的实现与验收边界

现有证据支持进一步调查 open-revo 的持续平台门控方案，但尚不能将其直接作为产品默认方案：平台值有其他 EC 语义，open-revo 也额外调整按键灯等状态。需验证原有性能模式、风扇曲线、按键和睡眠恢复不受影响。不能硬编码未知机型的平台原值，也不能向 ROM ID 写固定复位值。

实际充电验收需要从约 50%～55% 电量开始，先观察 60% 停充，再切至 80% 验证恢复和停充，最后切至 100% 验证取消限制后的恢复；同时记录电流、容量、门控和上限标志。再验证候选下限（55% / 75%）或固件自带回差，确认不会在临界值反复启停。本次没有强制放电，也没有留下持续的平台伪装或限充守护进程。

只有这些实际行为通过，才应把现有三档配置改成带百分比的产品选项。启动偏好保存应在硬件事务验证成功之后；显示应区分目标上限、当前门控、实时充电状态和错误，避免缓存值冒充实测状态。

## 1.4.0 产品接入

后续按用户要求继续实现，按钮最终保留“长效／平衡／工作站”，悬停用两行显示目标上限、恢复点和当前实际电量、充放电状态。实际电流保留在“更多信息”；80/60 停充及恢复点仍待充电实测，不能将协议读回当成真实充电闭环已验收。

- 三个 `charging_profile` 接口值不变，语义改为清除限制（100）、80/75、60/55；仅允许 BIOS `N.1.12MRO13`。
- 限充期间保留平台值 4；取消时清零上下阈值，在平台值 4 下触发存储，再恢复 7。不写 ROM ID 或存储地址本身。
- 旧 `0x07A6` bits5:4 清零，其他位保留，避免旧电压策略叠加。
- 成功必须同时满足门控、上下阈值、平台值和 WMI 存储读回；成功返回后服务才保存偏好。失败尝试回滚，回滚失败保留 dirty；状态不一致显示 unknown。
- 新增只读 `charge_limit`、`charge_resume`、`charge_gate`、`charge_reached`；服务增加这些字段及 `current_now`。旧驱动没有阈值接口时按钮禁用。
- 事务故障模拟覆盖逐项写失败、读失败、门控丢失、回滚失败后的显式恢复、ROM ID/BIOS 边界、百分比解码和取消。生命周期仍不写入限充，不增加温控/PWM 或自动修复循环。

### 本机产品验证

电池约 86–91%，AC0=0、Discharging。实际产品驱动依次设置 80/75、60/55、100/0，门控为 1、1、0；存储检查通过。办公模式、原曲线 `0 0 45 71 100 / 0 0 45 72 100` 和用户当前保存的响应速度 1300 ms 保持。首轮错误地固定断言之前的 1000 ms，导致提前退出；确认用户偏好已在 17:21 保存为 1300 后，改为与实验开始时快照比较并完整通过，没有覆盖用户新值。

安装 1.4.0 后，通过系统 D-Bus 设置 60/55；服务重启后保留。停止服务、重载驱动，在服务重放之前即读到相同阈值与门控；启动服务后仍一致。随后 D-Bus 设置 80/75，再取消为 100/0。最后恢复原偏好文件的全部字节，保持长效模式。

DKMS 1.4.0 已为 `6.12.116+deb13-amd64`、`6.19.13+deb13-amd64` 构建、签名并安装；当前已加载模块和系统服务二进制均为 1.4.0。默认检查、事务/生命周期测试与独立 GNOME 悬停测试通过；已检查悬停截图。

扩展文件已安装。当前 GNOME 会话缓存旧模块，新悬停与文字布局在下次登录生效；没有重启整个桌面。

证据：[产品设置实验](charge-presets-product-2026-11-10.log)、[安装后 D-Bus 和持久化实验](charge-presets-persistence-2026-11-10.log)。

**未完成的物理验收**：从低电量充到 60/80 停止、低于 55/75 恢复实际充电、取消后恢复实际充电、实际睡眠、整机重启和长期性能/按键灯行为。放电期间 reached=0 不能据此判断插电后的停充行为。当前是有读回与回滚的实验路径，上述待测项没有标为通过。
