## 四项接口判断

### 键盘灯光

`src/uniwill_leds.h` 根据 barebone ID、DMI quirk 和 0x0766 的 bit2 选择灯光类型。本机读取到了 RGB 标志；需要在受控加载后确认 LED class 实际创建及亮度、multi_intensity 接口，再做保存原值、短暂改动、读回、恢复的验证。

### 风扇

本机支持位和驱动 DMI 例外规则指向通用 EC 风扇控制路径。但 `R_UW_FANSPEED{,2}` 从 0x1804/0x1809 读取单字节控制读数，并不是从 0x0464/65 等读取实际 RPM。UI 的 RPM 必须另接真实测速通道，不能将该 ioctl 返回值标成 RPM。当前未读取或写入 0x180x，也未改动风扇表。

### 电池

驱动 charging_profile 提供 high_capacity / balanced / stationary 三种配置，不等于任意百分比上限。当前高容量配置可读，实际停止/恢复充电阈值尚未知。charging_priority 另有旧机型白名单，本机未匹配，不能因 charging_profile 支持就同时宣称充电优先级可用。

### 模式

本机没有匹配 profile_v1 的二档/三档列表，所以 `R_UW_PROFS_AVAILABLE` 按当前代码将返回 0（代码推断，未实际 ioctl）。补丁将本机加入 custom_profile_mode_needed，驱动意图采用自定义功耗/风扇控制。它不是直接复刻 Windows 三档。0xB0 按键处理仅发送 Super+Alt+F6；本机实际事件仍需按键实测。

## 为什么尚未加载原驱动

`uniwill_keyboard_probe()` 会无条件向 0x0751 写 0（代码注释称强制 balanced）、向 0x0741 写 1，并清零 0x044f；针对本机还会设置自定义配置位、初始化和启用键盘背光。卸载会清除手动位，但没有完整保存/恢复所有初始寄存器的机制。因此“加载看看”不是只读验证。

还存在 uw_show_hidden_bios_options()，但其 DMI 白名单不匹配本机，按当前代码不会在本机触发。不能将它误报为本机一定会修改 BIOS。
